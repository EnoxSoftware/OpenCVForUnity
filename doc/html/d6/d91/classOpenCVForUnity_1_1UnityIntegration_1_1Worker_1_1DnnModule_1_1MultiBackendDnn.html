Detailed Description

Subset of OpenCV OpenCVForUnity.DnnModule.Dnn for loading models that may run on either OpenCV DNN or Sentis (com.unity.ai.inference).

Backend id DNN_BACKEND_UNITY_SENTIS / DNN_BACKEND_UNITY_INFERENCE_ENGINE aliases SentisInferenceDnn.DNN_BACKEND_UNITY_SENTIS for Sentis. It is not the same value as OpenCV’s Intel OpenVINO backend constant OpenCVForUnity.DnnModule.Dnn.DNN_BACKEND_INFERENCE_ENGINE (different numeric id and vendor).

Call order must follow classic DNN usage: ReadNet → MultiBackendNet.SetPreferableBackend → MultiBackendNet.SetPreferableTarget → MultiBackendNet.GetUnconnectedOutLayersNames before inference (MultiBackendNet.SetInput / MultiBackendNet.Forward). Calling MultiBackendNet.GetUnconnectedOutLayersNames before both SetPreferable* calls will fail.

ReadNet(string) and ReadNet(string, int) only store the model path and engine; they do not load an OpenCV OpenCVForUnity.DnnModule.Net or construct a Sentis Worker until the backend and target are set on MultiBackendNet (see that type for deferred initialization details). The engine is applied on the OpenCV path only and is ignored on the Sentis path. The default engine is OpenCV ENGINE_AUTO: OpenCV tries the new DNN engine first and falls back to classic. The new engine does not support non-CPU backends; use ENGINE_CLASSIC when the OpenCV path will run on CUDA, OpenCL, or other non-CPU backends, and when the new engine produces incorrect results (including on CPU).
