Detailed Description

Concrete IMatSource that drives an injected IFrameGrabber and an optional IFrameOrientationCorrector. Owns _frameMat, a lazy _rotatedBuffer used only for user 90-degree rotation, and a lazy orientation scratch used only when orientation correction needs a swapped-size buffer and the output color format differs from the grabber. When user rotation is off, _rotatedBuffer is released. When the orientation scratch is not required, it is released. Grabber frames from IFrameGrabber.TryGrab are treated as read-only. Implements IMatTransformable only; IMatUpdateFPSControllable is implemented by derived sources such as ImageFileMatSource and by integration-layer mat sources that throttle texture readback. Also implements IMatSourceEvents, IMatSourceTickable, IMatSourceReinitializable, and IMatSourceDerivedFrames for host event subscription, per-tick acquisition, source-swap re-initialization, and derived frame registration.

Lifecycle events:

  • OnInitialized is raised on the thread that completes the underlying await continuation (for example after InitializeAsync).
  • OnFrameMatLayoutChanged is raised on the thread that commits the layout change (for example during Tick or initialization).
  • Layout-affecting settings (IMatTransformable.Rotate90Degree, IMatSource.OutputColorFormat) re-establish the output FrameMat layout and raise OnFrameMatLayoutChanged when the source is initialized, without requiring a new grab. When derived frames are registered, stale derived output buffers are synced to the new primary layout before OnFrameMatLayoutChanged is raised so handlers may read derived outputs safely. OnDerivedFrameLayoutChanged follows when a derived output layout changed.
  • OnFrameMatUpdated is raised at the end of Tick when DidUpdateThisFrame is true for that tick, after any registered derived frames are evaluated. Not raised by layout-only paths such as ReestablishFrameMatLayout outside Tick.
  • OnDerivedFrameLayoutChanged is raised when a registered derived frame's output layout (columns, rows, type) changes after the primary output layout is established during initialization, including immediately after layout-affecting DerivedFrameCollection.AddOrUpdateSettings while this source is initialized (without waiting for the next Tick). The first derived layout commit during initialization is silent, matching OnFrameMatLayoutChanged.
  • OnReleased is raised when ReleaseAsync completes and the source returns to MatSourceState.Uninitialized, including when initialization was in progress before OnInitialized. Does not require a valid FrameMat.
  • OnDisposed is raised on the thread that completes Dispose or DisposeAsync (for example the caller thread for synchronous Dispose, or the continuation thread for DisposeAsync).
  • OnErrorOccurred is raised on the thread that detected the failure.

Async lifecycle handlers may run on a different thread than the caller when internal paths use ConfigureAwait(false). Do not use host main-thread-only APIs in the handler unless you know the completion thread; marshal if needed.

◆ Dispose()

void OpenCVForUnity.Extensions.SourceToMat.MatSourceBase.Dispose ( )

Single-threaded hosts: This method performs synchronous blocking waits, which can cause deadlocks or hangs on runtimes without a thread pool (for example browser/WebAssembly targets). On such hosts, product teardown must call DisposeAsync; do not use this method. There is no safe way to wait for incomplete async work on a single-threaded host from IDisposable.Dispose.

Cancels in-flight initialization, waits for LifecycleTask (including on timeout), then waits for IFrameGrabber.CloseAsync (including on timeout). Also disposes the grabber when it implements IDisposable so native / device resources are released even if close did not finish.

◆ DisposeAsync()

async ValueTask OpenCVForUnity.Extensions.SourceToMat.MatSourceBase.DisposeAsync ( )

Asynchronously releases resources. Required on single-threaded hosts (for example browser/WebAssembly targets); do not use Dispose on those hosts.

Cancels in-flight initialization, waits for LifecycleTask (including on timeout), then waits for IFrameGrabber.CloseAsync (including on timeout). Also disposes the grabber when it implements IDisposable so native / device resources are released even if close did not finish.

Unlike ReleaseAsync, close is not awaited directly; a poll loop with Task.Yield lets the host SynchronizationContext pump while waiting. Do not use ConfigureAwait(false) on these waits so single-threaded hosts can resume on the captured host SynchronizationContext.

◆ Tick()

virtual void OpenCVForUnity.Extensions.SourceToMat.MatSourceBase.Tick ( float deltaTime = 0f)
virtual

Advances frame acquisition when the source is playing. Sets IMatSource.DidUpdateThisFrame only when a new frame is acquired.

Parameters
deltaTimeElapsed time since the previous tick, in seconds.

Sets DidUpdateThisFrame only when IFrameGrabber.TryGrab returns a new frame. When IFrameGrabber.TryGrab returns false, this tick is a no-op (not an error). Does not call IFrameOrientationCorrector.NotifyDisplayOrientationChanged; the host is responsible for that. Registered DerivedFrames are still evaluated when IFrameGrabber.TryGrab does not succeed so per-tick derived-frame flags such as IDerivedFrame.DidUpdateThisFrame stay in sync. Sources without a native frame rate (for example still images) may throttle Tick in a derived type that implements IMatUpdateFPSControllable.

◆ FrameMat

Mat OpenCVForUnity.Extensions.SourceToMat.MatSourceBase.FrameMat
get

Gets the owned reusable output buffer. Do not dispose this Mat.The returned Mat is reused every frame. Disposing it is unsupported. Implementations may log a warning and recreate the buffer on the next update when it was disposed accidentally. While MatSourceState.Initializing, uninitialized, or released, returns null.
