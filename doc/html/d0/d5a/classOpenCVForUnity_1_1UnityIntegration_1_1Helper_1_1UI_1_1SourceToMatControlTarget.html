Detailed Description

Thin facade that resolves either a MultiSourceToMatHelper or a SourceToMatHelperBase and forwards transport, transform, and read-only MatSource access through the helper public API.

Prefer assigning a MultiSourceToMatHelper when both components exist on the same GameObject. Capability get/set for the control panel goes through helper control contracts (IImageFileToMatHelperControls, IVideoFileToMatHelperControls, ICameraToMatHelperControls, ICameraFacingToMatHelperControls, IUnityTextureToMatHelperControls, IMatUpdateFPSToMatHelperControls), not by writing MatSource directly.

Controls contracts: *ToMatHelperControls interfaces are minimal mutation APIs for UI (path, loop, seek, device requests, and so on). Read-only values and diagnostics are not duplicated there; use concrete helper properties or MatSource capability interfaces instead.

Control panel defaults: SourceToMatControlPanel snapshots inspector defaults through SourceToMatControlPanelDefaults. Use GetCaptureIdentity to detect when the resolved multi helper or single helper instance changes and defaults should be re-captured.

◆ PullPerKindSettingsFromActiveHelper()

void OpenCVForUnity.UnityIntegration.Helper.UI.SourceToMatControlTarget.PullPerKindSettingsFromActiveHelper ( )

Pulls per-kind inspector settings from the active child helper into MultiSourceToMatHelper.PerKindSettings when the resolved target is a multi helper. No-op for a single-helper target.

Runtime UI (for example SourceToMatControlPanel) should call this after mutating per-kind Requested* values on the active helper so a subsequent MultiSourceToMatHelper.InitializeAsync Push does not overwrite panel changes with a stale cache.
