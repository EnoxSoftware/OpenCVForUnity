Detailed Description

Unity VideoPlayer-based IFrameGrabber for video files. Returns a new frame from TryGrab only when the player advances to a new frame. During playback, TryGrab also polls VideoPlayer.frame so frame delivery continues when VideoPlayer.frameReady events are not delivered.

Playback frame pipeline (hot path):

  1. HandleFrameReady or TryBeginCaptureFromPlaybackPoll calls BeginCaptureForFrame to issue a GPU readback for a new VideoPlayer.frame index.
  2. OnAsyncReadbackComplete stores the latest completed readback in _asyncGpuReadbackRequest and marks it ready to commit.
  3. TryGrab calls TryCommitPendingCapture at most once per tick to copy the latest completed frame into _frameMat and return it.

Frame-index dedup: at most one capture per video frame index is in flight, and a frame index is delivered at most once until playback wraps or seeks backward (ResetDeliveryTrackingForPlaybackWrap). _readbackGeneration invalidates in-flight readbacks on pause, stop, close, seek, and loop.

CloseAsync stops playback and releases frame buffers but keeps the bound VideoPlayer component for reuse. A player created by this grabber is destroyed only from Dispose. Externally assigned players are never destroyed.

OpenAsync uses UnityVideoPlayerOpenWait (Unity event + task waits) so Open suspends across player-loop frames after ConfigureAwait(false). Pause/seek uses UnityVideoPlayerOpenWait.WaitForPostPauseSettleAsync (post-pause player-loop tick counts). Play-time first frame wait uses UnityVideoPlayerOpenWait.WaitForFrameIndexAsync. The Open body runs inside SourceToMatSynchronizationContextScope.

Set RequestedUseAsyncGPUReadback before OpenAsync to request async GPU readback. Read EffectiveUseAsyncGPUReadback after open to observe the applied capture mode. When async readback is not requested or unsupported on the platform, synchronous render-texture copy is used instead.

Video file path: VideoFilePath is assigned to VideoPlayer.url during OpenAsync. It must be a VideoPlayer-loadable URL or absolute path before open. UnityVideoPlayerToMatHelper resolves inspector and API paths through SourceToMatUnityPath.ResolveVideoPlayerPath before initialization; callers that use this grabber or UnityVideoPlayerMatSource directly must resolve paths the same way or supply an absolute URI. See SourceToMatUnityPath.ResolveVideoPlayerPath for WebGL StreamingAssets HTTP URL rules and the difference from OpenCV SourceToMatUnityPath.ResolvePath.

Loop-off end-of-stream: When Loop is false, reaching the end of the stream sets HasReachedEndWithoutLoop to true, holds the last displayed frame (does not seek to the start), and subsequent TryGrab calls return false until playback is restarted (for example via SeekToStart and ClearEndReached).

◆ TryGrab()

bool OpenCVForUnity.UnityIntegration.Helper.SourceToMat.Grabbers.UnityVideoPlayerFrameGrabber.TryGrab ( out Mat frame)

Attempts to grab a newly available frame into a working buffer owned by the grabber.

Parameters
frameWhen this method returns true, the grabbed frame buffer owned by the grabber. Callers such as MatSourceBase treat this Mat as read-only and must not modify it in place. When this method returns false, frame is undefined.
Returns
true when a new frame was grabbed and is ready for the pipeline; false when no new frame is available for this call (normal for video / camera sources between frame updates). Returning false is not an error by itself.

During playback, begins capture from a VideoPlayer.frame poll, then commits the latest completed readback when available. Returns false when no new frame was delivered this tick (not an error).
