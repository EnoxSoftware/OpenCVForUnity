Detailed Description

Unity-specific SourceToMat integration notes and strict main-thread affinity for Helpers.SourceToMatHelperBase components.

This type is the single reference for custom Unity Extensions.SourceToMat.Grabbers.IFrameGrabber implementations. Shared marshaling and host-loop primitives live in SourceToMatHostMarshaling and SourceToMatHostWait (Extensions); this type adds Unity player-loop guidance and product grabber references.

Two layers after ConfigureAwait(false): Layer 1 marshaling and Layer 2 player-loop ticks via SourceToMatHostMarshaling and SourceToMatHostWait. Unity examples: bare Task.Yield does not advance VideoPlayer.isPrepared or WebCamTexture.didUpdateThisFrame.

Wait loops: Use SourceToMatHostWait.WaitUntilOnHostLoopAsync (contract: SourceToMatWait). Domain-specific outer retries (for example Grabbers.AsyncGPUReadbackOpenWait when UnityEngine.Rendering.AsyncGPUReadbackRequest.hasError is still true) may wrap HostWait calls; do not use Extensions.SourceToMat.InitTimeoutBudget.Token alone as the loop condition.

Helpers.SourceToMatHelperBase (strict affinity): capture Thread.ManagedThreadId and SynchronizationContext.Current in MonoBehaviour.OnEnable and use IsUnityMainThreadAffinity for UnityEvent bridging. That check is strict (thread id and captured context) so ConfigureAwait(false) continuations on the same thread still defer to the next MonoBehaviour.Update. Do not use SourceToMatSynchronizationContextScope for Helpers.SourceToMatHelperBase event bridging. Grabbers use thread-id-first marshaling via SourceToMatHostMarshaling (capture in the constructor on the Unity main thread).

Open wait strategies (inside SourceToMatSynchronizationContextScope):

  • Strategy A — Unity events + TaskCompletionSource<TResult> when Unity signals progress (prepareCompleted, frameReady, GPU readback callbacks).
  • Strategy B — Polling + SourceToMatHostWait when only per-frame flags exist (for example WebCamTexture.didUpdateThisFrame).
  • Hybrid: Strategy A for most waits, plus Strategy B where events are unreliable (for example post-pause settle ticks in Grabbers.UnityVideoPlayerOpenWait.WaitForPostPauseSettleAsync).

OpenAsync skeleton (player-loop grabbers):

  1. await SourceToMatHostMarshaling.EnsureCapturedMainThreadAsync (Layer 1).
  2. hostLoopContext = SourceToMatHostMarshaling.ResolveCapturedSynchronizationContext(mainThreadId, capturedContext).
  3. using (new SourceToMatSynchronizationContextScope(hostLoopContext)) around the full Open body (Layer 2).
  4. Inside the scope, Strategy A/B/Hybrid waits via SourceToMatHostWait or product OpenWait helpers.
  5. Complete OpenAsync only when the first TryGrab can succeed immediately.

Product references: Grabbers.UnityVideoPlayerFrameGrabber.OpenAsync and Grabbers.UnityVideoPlayerOpenWait (VideoPlayer); WebCam grabbers (permission via Extensions.SourceToMat.InitTimeoutBudget.RunOutsideTimeoutAsync

  • Grabbers.WebCamTextureGrabberUtils.WaitForCameraPermissionAsync, then didUpdateThisFrame polling); Grabbers.AsyncGPUReadbackFrameGrabber.OpenAsync with Grabbers.AsyncGPUReadbackRenderTextureCreateWait and Grabbers.AsyncGPUReadbackOpenWait.

CloseAsync: return SourceToMatHostMarshaling.RunOnCapturedMainThreadAsync with a synchronous CloseInternal (see Grabbers.UnityVideoPlayerFrameGrabber and Grabbers.AsyncGPUReadbackFrameGrabber). Scope is not required for close.

Custom Unity Extensions.SourceToMat.Grabbers.IFrameGrabber checklist:

  1. Follow the OpenAsync skeleton above. Resolve context before Scope; do not pass the raw captured context when ConfigureAwait(false) may have run.
  2. Prefer product OpenWait helpers: Grabbers.UnityVideoPlayerOpenWait, Grabbers.AsyncGPUReadbackRenderTextureCreateWait, Grabbers.AsyncGPUReadbackOpenWait.
  3. Keep Extensions.SourceToMat.InitTimeoutBudget.RunOutsideTimeoutAsync inside the same SourceToMatSynchronizationContextScope as the rest of Open (for example WebCam permission wait).
  4. Do not use ConfigureAwait(false) on awaits inside RunOutsideTimeoutAsync callbacks or grabber OpenAsync; WebGL continuations after long host waits may not resume on the Unity synchronization context otherwise.
  5. Complete OpenAsync only after the first TryGrab can succeed immediately, so callers avoid extra player-loop waits in Extensions.SourceToMat.Core.MatSourceBase.WaitForFirstFrameAsync.

Anti-patterns:

  • Layer 1 / Scope / bare Task.Yield mistakes (see SourceToMatHostMarshaling).
  • Waiting on frameReady alone after pause/seek when post-pause player-loop tick counts are required.
  • Calling Unity APIs from diagnostic code on paths where SynchronizationContext.Current is not the Unity context.

Returns whether the current execution has Unity main-thread affinity for the captured thread id and SynchronizationContext.

Helpers.SourceToMatHelperBase UnityEvent bridging only. Do not use this for grabber OpenAsync player-loop waits.

After ConfigureAwait(false), continuations may run on the same managed thread id with a different SynchronizationContext.Current. In that case this method returns false even when Thread.ManagedThreadId matches, so Helpers.SourceToMatHelperBase events defer to the next MonoBehaviour.Update.

Grabber marshaling uses SourceToMatHostMarshaling.IsCapturedMainThreadId via SourceToMatHostMarshaling.RunOnCapturedMainThreadAsync and SourceToMatHostMarshaling.EnsureCapturedMainThreadAsync (Layer 1 only). When mainThreadContext is null, only Thread.ManagedThreadId is compared.

Parameters
mainThreadIdManaged thread id captured on the Unity main thread.
mainThreadContextSynchronization context captured on the Unity main thread; may be null.
Returns
true when the caller has main-thread affinity; otherwise false.
