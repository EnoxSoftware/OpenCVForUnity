Detailed Description

Base class for processing workers that manage input and output Mats.

This class provides both synchronous and asynchronous execution modes for processing. All public methods in this class are thread-safe.

IMPORTANT:

  1. Execution Modes:
    • Synchronous: Execute() - Blocks until completion
    • Asynchronous: ExecuteAsync() - Returns immediately, runs in background
    • Only one operation (sync or async) can run at a time
  2. Accessing Results:
    • PeekOutput(): Returns a REFERENCE (submat) to internal buffer
      • Fast but unsafe across executions
      • Reference becomes invalid after next execution
      • Should only be used for immediate, read-only access
    • CopyOutput(): Returns a NEW copy of the result
      • Thread-safe and reliable
      • Recommended for most use cases
      • Required when storing results or sharing across threads
  3. Resource Management:
    • Implements IDisposable and IAsyncDisposable for proper cleanup
    • Dispose() / DisposeAsync() safely cancels running operations
    • Waits for completion with a default timeout when disposing
    • Automatically cleans up internal buffers
  4. Thread Safety:
    • All public methods are thread-safe
    • Internal buffers are protected by locks
    • Async operations use proper synchronization

Example Usage:

using (var worker = new ConcreteWorker())
{
void OnCompleted(ProcessingCompletion completion)
{
switch (completion.Kind)
{
case ProcessingCompletionKind.Succeeded:
break;
case ProcessingCompletionKind.Canceled:
break;
case ProcessingCompletionKind.Faulted:
if (completion.Error != null)
EngineLog.LogException(completion.Error);
break;
}
}
worker.ProcessingCompleted += OnCompleted;
// ProcessingCompleted is raised when each Execute / ExecuteAsync finishes (handler: ProcessingCompletion only).
// Synchronous execution
worker.Execute(input);
using (var result = worker.PeekOutput())
{
// Process result safely
}
// or
using (var result = worker.CopyOutput())
{
// Process result safely
}
// Asynchronous execution
await worker.ExecuteAsync(input);
using (var result = worker.CopyOutput())
{
// Process result safely
}
worker.ProcessingCompleted -= OnCompleted;
}

virtual void OpenCVForUnity.Extensions.Worker.ProcessingWorkerBase.Cancel ( )
virtual

Cancels the current processing operation if running.

Cooperative teardown signal for in-flight work. This method is thread-safe. It has the same effect as canceling the token passed to ExecuteAsync. Disposal already cancels running work; hosts may call this during teardown while DisposeAsync is still in progress.

After Dispose or DisposeAsync, this method returns without throwing so teardown is not faulted by a redundant stop request.

Execute, ExecuteAsync, and related entry points still throw ObjectDisposedException after dispose because they continue use of the worker.

◆ Dispose() [1/2]

void OpenCVForUnity.Extensions.Worker.ProcessingWorkerBase.Dispose ( )

Releases resources used by the worker.

This method is thread-safe and ensures proper cleanup of resources:

  • Cancels any running processing operation
  • Waits for operation completion with a timeout (DEFAULT_DISPOSE_OPERATION_WAIT_TIMEOUT)
  • Disposes all managed resources (Mats, CancellationTokenSource)

Multiple calls to Dispose are allowed but only the first call will release the resources. If a running operation doesn't complete within the wait period (typical processing takes less than 200ms), it will be forcefully terminated.

Single-threaded hosts: This method performs synchronous blocking waits, which can cause deadlocks or hangs on runtimes without a thread pool (for example browser/WebAssembly targets). On such hosts, prefer DisposeAsync.

Exceptions
ObjectDisposedExceptionThrown when trying to access a disposed instance.

virtual async Task OpenCVForUnity.Extensions.Worker.ProcessingWorkerBase.ExecuteAsync ( CancellationToken cancellationToken = default)
virtual

Executes processing asynchronously with pre-set inputs.

This method is thread-safe. Only one processing operation (sync or async) can run at a time - calling this method while another operation is in progress will throw an InvalidOperationException.

IMPORTANT: When using async execution, you must:

  1. Use CopyOutput() instead of PeekOutput() to retrieve results
  2. Check IsRunning property to verify the operation status
  3. Handle the cancellation token appropriately if needed

The method creates a snapshot of inputs by storing references (not deep copies) to the input Mats, and the referenced Mats must not be modified or disposed until the async operation completes to ensure consistency. The internal output buffer may be modified during async operation, so direct references obtained via PeekOutput() are not safe to use.

◆ PeekOutput()

virtual Mat OpenCVForUnity.Extensions.Worker.ProcessingWorkerBase.PeekOutput ( int index = 0)
virtual

Returns a reference (submat) to the output Mat at the specified index.

This method is thread-safe but has important usage constraints:

IMPORTANT:

  1. The returned Mat is a REFERENCE (submat) to the internal buffer:
    • Any modifications to the returned Mat will affect future results
    • Disposing the returned Mat is safe and does not dispose the internal buffer itself; only the submat handle becomes invalid
    • The reference becomes invalid after the next Execute/ExecuteAsync call
    • The reference becomes invalid if the worker is disposed
  2. Thread Safety Considerations:
    • DO NOT use with ExecuteAsync() as the internal buffer may be modified during async operation
    • Even with Execute(), the returned reference is only valid until the next execution
    • For thread-safe access to results, always use CopyOutput() instead

Best Practices:

  • Use CopyOutput() if you need to:
    • Store the result for later use
    • Modify the result
    • Share the result across threads
  • Only use PeekOutput() when:
    • You need immediate read-only access to the result
    • You will complete all operations before the next Execute call
    • Performance is critical and you understand the risks

Returns
A reference to the internal output Mat. DO NOT store this reference.

virtual void OpenCVForUnity.Extensions.Worker.ProcessingWorkerBase.WaitForCompletion ( TimeSpan? timeout = null)
virtual

Waits for the current processing operation to complete with a timeout.

This method is thread-safe and can be safely called from any thread. If no processing operation is running, returns immediately. If the operation doesn't complete within the specified timeout, throws TimeoutException. This method works for both synchronous (Execute) and asynchronous (ExecuteAsync) operations.

Single-threaded hosts: This method performs synchronous blocking waits, which can cause deadlocks or hangs on runtimes without a thread pool (for example browser/WebAssembly targets). On such hosts, prefer WaitForCompletionAsync(TimeSpan?).

Parameters
